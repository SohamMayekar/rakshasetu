# imports · a volunteer's messy spreadsheet, read safely

- **What it does (m29):** a call-taker or officer uploads a CSV or XLSX on the desk (`POST /v1/imports`, local listener, `import.run`). The file is stored by its SHA-256 (never overwritten), the headers are mapped by a **team-owned synonym list** (`config/sheet_headers.yaml`: `naam`/`नाम` → name, `mob` → phone, `kitne log` → headcount, `gaon` → village, `samay` → time …), and the first 8 rows are previewed **as they will be read**, with every flag. **A person confirms the mapping** (`POST /v1/imports/{id}/mapping`) before any row is imported; the event log records which columns they changed from the proposal.
- **Key table:** `imports` (file hash, headers, proposed and confirmed mapping, preview, counters, status `uploaded → mapped → running → done`).
- **Reading safely:** `.xlsx` through openpyxl read-only with `data_only=True`: **cell values only, a formula is never evaluated** (a formula with no saved value reads as empty). `defusedxml` is installed, so openpyxl refuses XML entity tricks. CSV is read as UTF-8 (with or without a BOM), then cp1252; cp1252 or garbled-looking text (`à¤`, `Ã`) is flagged in the preview. **Caps:** 5 MB, 5,000 rows, 40 columns, 1,000 characters a cell. A sheet over a cap is **refused with the reason**, never silently truncated.
- **The tricky rule, the Excel-damage guard:** Excel shows numbers of 12+ digits in exponential notation and keeps 15 significant digits (VERIFIED, Microsoft support). If a sheet is saved as CSV in that state, `919876543210` becomes `9.19877E+11`; the last digits are gone. So a phone in E-notation, or ending in 4+ zeros, becomes **null**, is flagged "phone damaged by Excel", and is **never used as identity** (so it can't cause a merge). A real `.xlsx` keeps the full number, and it reads fine.
- **Other normalisation:** phones to E.164 (`098765-43210`, `+91 98765 43210` → `+919876543210`); headcounts `"six"`, `"6 log"` → 6 stated, `"5-6"` → 6 **estimated**, `"about 10"` → 10 estimated; times are IST, and a day/month that reads both ways (`03/10`) takes **the reading closest before the import**, flagged so a person sees the choice; a date in the future is "time not readable"; rows older than 12 hours are flagged "old report: confirm before sending a team"; `done`/`rescued`/`✓` in the status column marks a row as already done.
- **Scope:** imports are visible only inside the uploader's incident and district (in the SQL); an Odisha officer can't upload into Bihar, and a Muzaffarpur officer can't see a Gopalganj import.
- **How to show it:** drop the demo sheet; the preview shows row 2: `9.19877E+11` → "phone damaged by Excel", `5-6` → "6 (estimated)", `03/10` → "3 Oct, read as the closest before the import".
